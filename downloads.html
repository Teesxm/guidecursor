MACOS PRODUCT DIRECTION

Designed for macOS.Proved first in the browser.

GuideCursor is intended to become a native macOS application that works alongside existing accessibility tools. The current course MVP is a browser simulation of the core Mail journey, used to test the interaction model before native integration.

CURRENT STATUSCOURSE MVP

Browser MVP now, native macOS next

The current artifact demonstrates the Mail → file picker → Open journey, Low Vision and Blind guidance, ambiguity handling and the rule that the user makes every click. It does not yet read a live macOS Accessibility tree or ship as a native application.

✓ End-to-end Mail journey in the browser
✓ Low Vision and Blind guidance modes
✓ User clarification when several CV files match
✓ User-controlled final actions
△ Native Accessibility API integration remains future work
01 · CURRENT MVP

The interaction model works in the browser.
Native integration comes next.

The course MVP is intentionally a web simulation. It demonstrates the value-creating mechanism from goal to verified guidance without claiming that the native macOS infrastructure already exists.

IMPLEMENTED IN MVP

Mail + file-picker journey

The user can request “attach my CV”, reach Attach, clarify between matching files, select the intended file and reach Open.

IMPLEMENTED IN MVP

Visual guidance

Low Vision mode shows a high-contrast target and a live direction cue while the user controls the pointer.

IMPLEMENTED IN MVP

Blind guidance

Blind mode uses spoken target/task messages, non-speech directional tones and target confirmation while the user keeps control.

IMPLEMENTED IN MVP

Clarification instead of guessing

If several CV files match, GuideCursor asks the user which one they mean before guidance continues.

PLANNED NATIVE PRODUCT

macOS Accessibility API + local inference

The final product is designed to read live controls through the Accessibility API, use local processing by default and fall back carefully when metadata is incomplete.

NOT YET IMPLEMENTED

Native Swift application

A native app, live Accessibility permission path, Ollama integration, on-device recognition and macOS Zoom integration remain future implementation work.

02 · CURRENT BOUNDARIES

One journey first.
Focused by design.

The current MVP supports one end-to-end browser journey based on Apple Mail and its file-selection window. Other tasks and platforms remain outside the initial scope.

SUPPORTED IN COURSE MVP

Attach a CV in Mail

The prepared file picker contains the test CV files used in the demo. Searching across folders or the wider computer is outside the current evaluation.

NOT YET SUPPORTED

Broader tasks, platforms and impairments

Safari tasks, Windows, hearing-focused assistance, motor-focused assistance and broad application coverage are future possibilities, not current MVP features.

03 · NEXT VALIDATION STEP

What a native follow-up must prove.

The next step is not “shipping” the browser prototype. It is testing the same core journey with a native macOS implementation and intended users.

Native pilot journey

Open a draft email in Mail, request “attach my CV”, verify Attach through live interface data, transition into the prepared file picker, clarify ambiguous files if needed, then verify and guide to Open without GuideCursor performing the click.

1. Accessibility permission and live control reading work reliably
2. Attach is identified within the target response time
3. The file picker is re-read after the user click
4. Ambiguous files trigger clarification
5. Blind and Low Vision guidance remain usable with existing tools
6. Intended-user testing measures success, errors, time, workload and control

Browser MVP, native product direction.

The website demonstrates the interaction model and documents the planned privacy, verification and deployment architecture. It does not claim that a production macOS application is already available.
