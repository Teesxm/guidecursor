OCTOBER 2026 · MVP SCOPE

One journey.Prove it works.

The earlier GuideCursor concept was broad. The current MVP is intentionally narrow: people with a visual impairment using macOS, one end-to-end journey in Apple Mail, and two stretch tests only after that journey works reliably.

CORE MVPAttach a file to an email in MailIncluding the file-selection window. GuideCursor guides; the user makes every click.
ONLY AFTER CORE RELIABILITYSafari + menu commandTwo stretch tests for generalisation.
01 · CORE JOURNEY

From “attach my CV”
to Open.

GuideCursor re-reads the interface after every user action. It does not follow a fixed script and it does not choose the file or confirm an action for the user.

02 · STRETCH TESTS

Generalise carefully.

These are not parallel MVP features. They are evidence tests added only after the Mail journey is reliable.

CORE

Apple Mail + file picker

The only end-to-end journey the MVP must implement. It crosses two windows and tests target verification after state changes.

STRETCH 1

Download from Safari

Tests whether the same candidate-and-verification approach transfers to another Apple application.

STRETCH 2

Find a menu command

Tests controls exposed through the macOS menu structure after the primary workflow is stable.

03 · OUT OF SCOPE

Not promised in version one.

Narrowing the scope is part of the product decision, not a missing section of the site.

WindowsPossible later platform; not part of the current MVP.
Hearing supportRemoved from the first version to focus on visual impairment.
Motor supportRemoved from the first version; no snapping or stabilization claim.
Autonomous completionGuideCursor does not click, type, select files or confirm for the user.

The MVP succeeds by being specific.

One user group, one platform, one core journey and measurable reliability before expansion.
