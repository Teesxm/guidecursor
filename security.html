SECURITY & TRUST · MACOS

AI cannot inventwhere to click.

GuideCursor separates language understanding from target selection. The model can interpret the user’s goal, but guidance only starts after the chosen target is checked against controls that exist in the current macOS window.

VERIFIED TARGET BOUNDARY
1 · macOS exposes real controlsRole, label, state and position from the Accessibility API.
2 · Screen recognition fills gapsOn-device screenshot candidates are lower confidence, not automatically trusted.
3 · AI chooses from a numbered listAnything outside the supplied candidate list is rejected.
4 · Live verification happens before guidanceThe target must exist, be visible, enabled and clickable.
5 · The user still clicksGuideCursor never completes the action on the user’s behalf.
01 · VERIFIED TARGET PIPELINE

Interpret broadly.
Guide narrowly.

The architecture is deliberately asymmetric: AI can reason about meaning, but guidance must stay grounded in controls the system has actually observed.

1READ

Accessibility API

Read the active window’s accessible controls with user permission.

2ADD

Visual candidates

Use on-device recognition when controls are unlabelled, marking those candidates as less certain.

3INTERPRET

Structured model output

Return a candidate number, alternatives, confidence and the proposed next step.

4VERIFY

Live window check

Reject missing, hidden, disabled, non-clickable or invented candidates.

5GUIDE

Local pointer loop

Once verified, update cues from pointer geometry without another AI response for each movement.

02 · UNCERTAINTY HANDLING

When confidence drops,
GuideCursor slows down.

If GuideCursor cannot establish one verified target, it asks for clarification or falls back instead of pretending certainty.

AMBIGUOUS

Several plausible controls

GuideCursor describes the alternatives by label and position and asks the user to choose before guidance begins.

No silent tie-breaking when alternatives are genuinely plausibleUser confirmation becomes part of the interaction
NO VERIFIED TARGET

Say so, then offer a fallback

The system can offer a known menu shortcut, ask the user to rephrase, or let the user continue with VoiceOver or Zoom.

Long-running identification surfaces an explicit fallbackOne keyboard shortcut immediately stops all speech and guidance
03 · PRIVACY BOUNDARY

Local by default.
Cloud only by choice.

Work screens can contain email, documents and personal information. GuideCursor therefore keeps screenshots and routine processing on the user’s Mac whenever possible.

DEFAULT

On-device / Ollama

Local processing keeps screen context on the Mac, works offline and avoids per-request cost. Local inference is used only where the selected model meets the required accuracy and response-time threshold.

Screenshots stay on deviceModel receives local text candidatesNo internet required for local mode
OPT-IN

Cloud model

A cloud model may be more capable but introduces third-party processing, connectivity requirements and usage cost. It is therefore opt-in in the current architecture.

Never receives screenshotsReceives only the text candidate listCompared against local inference on the same accuracy and response-time tasks
04 · KNOWN BOUNDARIES

What GuideCursor does not hide.

Verification reduces risk, but it does not make target identification infallible. These are product boundaries that remain visible in the design.

Incomplete accessibility dataApplications expose different amounts of metadata; screen recognition only partly closes the gap.
Wrong targetVerification cannot guarantee perfect identification, so confirmation before the click remains important.
Powerful macOS permissionAccessibility access can read content in other applications; employers need a clear explanation of what is read and stored.
Platform competitionApple or Microsoft could extend general assistants toward the same user group; co-design and specialist adoption are part of the response.

Trust without certification theatre.

GuideCursor is still in pre-release development. It does not currently claim SOC 2, ISO certification or an independent penetration test. Trust comes from a constrained architecture, explicit permission boundaries and transparent release status.
